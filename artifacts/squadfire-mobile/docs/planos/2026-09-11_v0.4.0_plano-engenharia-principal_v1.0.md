# SQUADFIRE — v0.4.0
## Principal Engineering Implementation Plan
### Earth Planet • Long Fixed Stages • Far-Horizon Spawns • Squad Power 0–500 • 10:1 Visual Compression

> **Status:** APPROVE WITH REQUIRED CHANGES  
> **Purpose:** This document supersedes the previous v0.4.0 implementation plan. It incorporates a read-only review of the actual Replit codebase and the concrete architecture currently present in `artifacts/squadfire-mobile`.
>
> **Do not implement anything that contradicts this plan.**
>
> **Priority order:** correctness → regression safety → deterministic behavior → maintainability → performance → visual polish.
>
> **No code outside the requested scope should be changed unless technically necessary to preserve existing behavior.**

---

# 0. EXECUTIVE DECISION

The v0.4.0 direction is valid and fits the current architecture without requiring a major rewrite.

However, the previous plan contained four major problems that must be corrected before implementation:

1. The proposed `buffedCount + remainder normals` representation can exceed 50 visible units:
   - `499 = 49 buffed + 9 normal = 58 visible units`.
   - This violates the intended visual cap and the current formation/projectile-pool assumptions.
2. Moving enemies to the far horizon without resizing the spatial collision grid would make distant enemies visually present but unhittable.
3. The current spawn scheduler can silently discard scheduled enemies when `maxAlive` is reached while still advancing its cursor.
4. The currently proposed boss HP values are numerically consistent with rifle damage, but likely far too low relative to the current gate cadence and upgrade accumulation.

These points are mandatory to address.


Expected for Earth:

```text
AND
spawnedRegulars === StageConfig.enemyCount

required boss dead
```

# 15. CURRENT FAR DEPTH — VERIFIED

Current camera produces approximately:

```text
farVisibleDepth ≈ 23 world units
```

for supported layouts.

Old regular spawn:

```text
~7.8
```

Old boss spawn:

```text
~7.9
```

# 16. FAR SPAWN INSET

Do not spawn exactly at `farVisibleDepth`.

Need margin for:
- group depth jitter;
- second-row group offset;
- enemy depth tolerance;
- boss depth tolerance;
- visual fade-in.

Use:

```ts
enemySpawnDepth =
  farVisibleDepth -
  farSpawnInset;
```

Derive/test a safe inset.

Required invariant:

```ts
maxEnemyHittableDepth
<
farVisibleDepth;
```

For all supported camera layouts.

---

# 17. SPATIAL COLLISION GRID — MANDATORY CHANGE

Current collision grid only covers roughly:

```text
world y up to ~9.5
```

A regular enemy spawning around:

```text
21–22
```

would not be inserted into the spatial grid.

Therefore distant enemy would be visually present but projectile collision would miss it.

Mandatory:

Dimension the grid from the camera-derived far depth.

Conceptually:

```ts
gridMaxDepth =
  spawnGeometry.spatialGridMaxDepth;
```

and compute bucket rows accordingly.

Required test:

```text
enemy spawned at far spawn depth
→ immediately belongs to a valid collision bucket
→ can be hit on the first valid projectile sweep
```

No enemy may exist in a hittable region outside the grid.

---

# 18. COMBAT DEPTH

Current fixed depth cutoff must be retired for Earth.

New:

```ts
combatDepth =
  max(
    maxRegularHittableDepth,
    maxBossHittableDepth,
    any other actually hittable gameplay object depth
  );
```

Projectiles beyond this depth may skip enemy collision lookup only after the computed limit.

Do not use old hardcoded depth ~8.9.

---

# 19. GATES AND FAR SPAWN

Current gate depth can remain closer to the player if gates are not projectile targets.

Do not move gates to the horizon automatically.

Reason:
- distant gate choice would be unreadable;
- the player must have enough visual time to choose;
- gate semantics are separate from enemy spawn semantics.

Only include gate depth in `combatDepth` if the actual collision system requires it.

---

# 20. BOSS FAR ENTRY — PACING FIX

Current boss approach speed from far spawn would cause approximately:

```text
~33 seconds
```

of approach before reaching its existing hold position.

This is too slow unless explicitly intended.

Do not simply reuse old approach speed.

Define boss approach pacing in semantic time.

Recommended target:

```text
8–12 seconds from far spawn
to intended combat hold zone
```

Then derive approach speed from:

```ts
distance / targetApproachSeconds
```

This keeps pacing consistent if camera/far depth changes later.

Do not hardcode a speed that only works for the current spawn depth.



```text

```


```text

```

# 25. CORRECT VISUAL DECOMPOSITION

Use:

```ts
fullUnits = Math.floor(squadPower / 10);

visibleUnits =
  fullUnits +
```

# 50. INITIAL SQUAD POWER

Current initial squad is 5 visible Soldiers.

Under corrected compression, if Power1–9 were represented by one partial unit, this would visually change the opening.

This needs a compatibility decision.

To preserve the current opening visual/gameplay, use a special early-power representation rule:

```text
For squadPower 1..9:
render one normal Soldier per Power point.

For squadPower >= 10:
compress complete groups into Power10 units
and represent the final remainder using at most one partial unit.
```

This yields:

```text
5 power → 5 normal Soldiers
9 power → 9 normal Soldiers
10 power → 1 Power10 Soldier
13 power → 1 Power10 + 1 Power3 partial
29 power → 2 Power10 + 1 Power9 partial
499 power → 49 Power10 + 1 Power9 partial = 50 visible
500 power → 50 Power10
```

This preserves the current early-game visual and still guarantees a maximum of 50 visible units after compression.

IMPORTANT:

The reconciler must support the discontinuity:

```text
9 visible normals
→ 10 power
→ 1 Power10 unit
```

with the transformation pulse.

# 51. VISIBLE UNIT COUNT FORMULA

Use:

```ts
function visibleUnitCount(power: number): number {
  if (power <= 0) return 0;
  if (power < 10) return power;

  const full = Math.floor(power / 10);
  const rem = power % 10;

  return full + (rem > 0 ? 1 : 0);
}
```

Examples:

```text
1 → 1
5 → 5
9 → 9
10 → 1
13 → 2

100 → 10
499 → 50
500 → 50
```
